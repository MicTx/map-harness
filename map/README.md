# Map Harness — map layer slots

English | [中文](README.zh.md)

Map Harness is built on [DeepSeek Harness](../README.upstream.md) (the upstream). This directory is the **only owned-code area** of this repository: branding, map tools, patches, and profiles all live here, mounted through the upstream official extension mechanisms, **without modifying any upstream file**.

## Slot contract

## Build and run

A clean checkout has two build owners: the upstream root builds upstream packages, then the map aggregate builds every package linked by the wrapper. `build-web.mjs` runs the map aggregate before rebuilding the Web frontend.

```sh
pnpm install
pnpm run build
node map/bin/build-web.mjs
node map/bin/map-harness.mjs --no-open
```

When upstream artifacts and the Web frontend are already current, `node map/bin/build.mjs` rebuilds only the map runtime packages.

## Tests and engineering gates

`node map/bin/test.mjs [--build]` runs every map-owned suite in dependency order: per-package source-plane specs, the engineering topology/manifest gates, the built-artifact smoke, and the real-Loader `--dump-config` composition smoke. The browser-level composition e2e stays its own lane (`pnpm --filter @map-harness/arcgis-mcp run test:composition`). Owners, dependency direction, planes, Config/credentials/health/shutdown protocol, and the release checklist live in [docs/engineering.md](docs/engineering.md).

## Invariants (closing gate)

1. **Zero content changes to upstream files**: `packages/`, `apps/`, `vendor/`, `scripts/`, `docs/`, `snapshots/`, and root-level upstream configs all stay verbatim, with the documented exceptions in [UPSTREAM.md](./UPSTREAM.md) (the `map/*` workspace line in `pnpm-workspace.yaml`, the CSS virtual-id compatibility patch in `packages/client/tsdown.client.ts`, and the repo-owned root facade files registered there).
2. **Upstream does not know about the map layer**: upstream code never imports anything inside `map/`; the `map/` layer attaches one-way through Cordis patch/slot mechanisms only.
3. **Upstream identifier exemption**: strings such as `@deepseek-ai/`, `dsh`, `DSH_*`, and `FishLogo` inside upstream files are upstream file content arriving with upstream updates and do not count as brand leakage of this repository; this repository's brand appears only in `map/` layer artifacts (browser brand row, profile name, CLI name).
