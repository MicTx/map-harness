## Install guide for LLM agents

Install map-harness {{version}} from a script-launched Web service archive attached to this release. The package includes its native service executable, locked Node engine, compiled map core, helpers, launchers, manifest, and licenses. No Node.js installation, desktop installer, or source build is required.

1. Match the operating system and CPU of the service host to an attached asset: `mac-arm64`, `mac-x64`, `linux-arm64`, `linux-x64`, or `win-x64`. Linux targets use GNU libc. `web-service-release.json` identifies the targets and attachments qualified for that release; an absent target is unsupported. The browser's platform does not determine the service-host target. Do not substitute another architecture, an automatic Source code archive, a CLI ZIP, or a desktop installer.
2. Download `map-harness-{{version}}-web-<target>.tar.gz` for macOS/Linux or `.zip` for Windows, plus `SHASUMS256.txt`. Compare the archive's SHA-256 with its line in the checksum file using `shasum -a 256` or PowerShell `Get-FileHash -Algorithm SHA256`, then extract it. Success: the folder contains `start-web.sh` or `start-web.cmd`, `web-service-manifest.json`, a target directory with the native service and helpers, and the license files. Keep the entire folder together.
3. On macOS/Linux run `./start-web.sh`; on Windows run `start-web.cmd` from the extracted folder. Windows uses its installed Windows PowerShell; no system Node.js or Python is required. The launcher sees only environment variables that already exist in this shell, so export optional provider variables such as `DEEPSEEK_BASE_URL` before starting it; a `.env` file must not supply `DEEPSEEK_BASE_URL`. The launcher uses the packaged native runtime to verify the manifest and every listed file before configuration or service startup.
4. Follow the guided prompts: confirm the displayed data directory, then paste your own `DEEPSEEK_API_KEY` when asked. Input is hidden and confirmation is required. The key is saved by the product credential service in `$MAPHARNESS_HOME/.credentials.yaml` (default `~/.map-harness`), never in the extracted package. An existing saved key is reused; a key supplied by the environment or `.env` may be used directly or saved after confirmation. Optional geographic-provider keys are configured separately; missing optional keys do not prevent startup. Never invent, log, or commit a key.
5. The service checks the actual Web page and prints its full token URL, `http://127.0.0.1:6425/?token=...` by default (`--port <n>` changes the port). Open that URL in the browser. Keep the terminal open to keep the service running; press Ctrl-C to stop. On Windows, confirm the CMD batch termination prompt if it appears. Noninteractive use requires a saved key or `DEEPSEEK_API_KEY` set in the environment before launch. For unattended service invocations without guided configuration, add `--no-onboarding` before the other Web arguments.

Launcher arguments are forwarded to the Web service; the service listens on `http://127.0.0.1:6425` unless `--port <n>` is present. `MAPHARNESS_HOME=<dir>` isolates application state; the default is `~/.map-harness`, separate from a stock DeepSeek Harness installation and its legacy shared data. To move selected old sessions across, use the release's explicit `manage import` flow against a readonly snapshot (dry-run first; apply the saved ready plan with `--apply --plan`). Keep user state outside the program folder. To update, stop the old service, extract the new release beside or over the old program folder, and start the new launcher. If verification fails, download the release again; there is no source fallback.

The browser receives map display and interaction JavaScript. Map analysis and business implementations run as compiled code in the local service.
