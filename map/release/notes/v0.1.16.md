## What's new

**New**
- **Independent installation**: Map Harness now runs on its own data root (`~/.map-harness` by default, `MAPHARNESS_HOME` to override) and no longer shares the stock DeepSeek Harness data root. Sessions, credentials, schedules, caches, and browser state stay in the Map instance.
- **Per-user managed install**: extract the managed package, verify its release identity, and install into `~/Applications/Map Harness`, `%LOCALAPPDATA%\Programs\Map Harness`, or `~/.local/opt/map-harness` with `install-map.sh`/`install-map.cmd`; `map-harness manage status` and `doctor` inspect the installation without starting a service.
- **Explicit legacy import**: `map-harness manage import` plans a dry-run from a readonly snapshot, copies only selected Map sessions and their attachment/map-resource closure, and never modifies the old root or copies credentials, `.env`, schedules, or shared agents.

**Changed**
- **Single writer per data root**: a second service on the same data root reports `MAP_INSTANCE_BUSY` instead of attaching; Map Web listens on the fixed default port `6425` (`--port` overrides it).
- **Isolated browser state**: Map browser storage and cookies are namespaced by instance, so a Map instance no longer reuses a stock DeepSeek Harness browser state on the same origin.
